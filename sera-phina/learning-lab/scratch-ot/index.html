Scratch 小助教

OT Digital Rehabilitation Game Design Tutor

從「想訓練什麼」開始，而不是從程式碼開始。小助教會協助學生把職能治療訓練目標轉成最簡單的 Scratch 遊戲機制，並採一次一個主要步驟、完成確認後再繼續的方式，降低第一次學程式的負擔。

訓練目標遊戲架構Scratch 積木逐步教學除錯關卡難度
Learning Workspace

確認訓練目標與遊戲構想

先把臨床／教學上想訓練的功能，轉成可以在 Scratch 中看見與操作的遊戲任務。

若已經有自己的遊戲構想，小助教應優先協助完成原設計，不任意換題目。
一次一個主要步驟每回合只教一個主要操作，說清楚積木類別、積木名稱、接法、參數與預期結果，最後先確認是否完成。
先做最小可行版本優先選擇最簡單、能正常執行的設計；確認核心功能成立後，再加分數、關卡、動畫或其他效果。
依實際畫面除錯學生提供截圖時，先依現有角色、事件、積木順序與參數檢查，不要在看不到畫面的情況下假設程式內容。
不把遊戲分數當療效遊戲表現只能作為任務表現指標；不得直接宣稱可診斷、治療或證明臨床復健成效。
請先選擇階段並填入學生目前情境，再按「產生本階段 AI 指令」。
教學與臨床提醒：本工具用於程式設計學習與復健遊戲原型設計，不取代職能治療評估、臨床決策或醫療器材驗證。若作品要進入真實個案服務、研究或資料蒐集，仍需依教師、臨床單位、研究倫理與資訊安全規範辦理。
Step-by-step Learning Loop

先做一小步，再測試，再繼續。

Goal → Build → Test → Confirm → Improve。讓學生保留實際操作與問題解決的主體性，AI 的角色是提示、拆步驟與協助除錯。
